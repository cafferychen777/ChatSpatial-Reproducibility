EXPERIMENT B-X — PRE-SPECIFIED RULES (written 2026-10-09, before any experiment-B-X run, pilot included)
=====================================================================================================
Scope: an assumption-violation probe panel, and a re-run of the DLPFC head-to-head on all 12 sections (one
backend; STAgent and SpatialAgent as the code-generating arms).
Code: scripts/ (on the cluster at $CHATSPATIAL_WORK_DIR/expBX/scripts).
Raw outputs: $CHATSPATIAL_WORK_DIR/expBX/{runs,judge,tasks,logs}; result tables in results/. Any change after this file is written is logged in section 6 with its date and reason.

1. COMMON SETTINGS (both parts)
1.1 Backend: claude-sonnet-5-5 for every system, every arm, and the probe judge (claude-sonnet-4-20250514, used
    in May 2026, is retired). Provider defaults: no temperature is sent (the model rejects explicit
    temperature), thinking and effort not set (provider default: adaptive thinking, default effort),
    max_tokens 16000 per response for every system (thinking tokens count against it). No server-side model
    fallback. A response with stop_reason "refusal" is kept and scored as whatever the run then did.
1.2 Systems.
    - ChatSpatial: PyPI 1.5.5 in conda env chatspatial_v155 (the experiment-B v1.5.5 env; SpaGCN in its
      default published-1.2.7 mode; R 4.4 with spacexr, CARD, SPARK, CellChat; BayesSpace not installed),
      same R isolation and SpaGCN scipy shim as experiment B. Harness expBX_chatspatial_agent.py: the LLM gets
      all 20 tools of the ChatSpatial MCP server with their full published JSON schemas (native tool calling,
      tool_choice auto) and the server's own instructions, as an MCP client presents them; tools execute
      in-process through the MCP server's call_tool; a tool exception is returned as an is_error tool_result
      carrying the exception text (what an MCP client receives). System prompt: one neutral sentence (assistant
      connected to the ChatSpatial MCP server; carry out the request; report the outcome) + server
      instructions. At most 30 assistant turns.
    - STAgent (git 054cc64) and SpatialAgent (git e51ec0f): code-generating agents, ported to the CPU cluster as Linux
      venvs with the same package versions as the original macOS venvs of the May/Aug 2026 head-to-heads
      (no packages added; no R). Drivers expBX_driver_{stagent,spatialagent}.py reproduce the original drivers'
      configuration (STAgent: invoke_our_graph, recursion limit 50, emit_conflict_message False, cwd = output
      directory; SpatialAgent: data_path = directory holding the input, tool_retrieval llm,
      auto_interpret_figures False, act_timeout 600 s, recursion limit 50). Changes needed for the backend only
      (patch diff: competitors/PATCHES.diff in the work directory; verified by smoke tests 2723941/2723943/2723944):
      (a) no temperature sent; (b) max_tokens 16000; (c) claude-sonnet-5-5 rejects a request whose last message
      is an assistant message (prefill), which both agents send after every executed step (STAgent after a
      tool's analysis step; SpatialAgent stores observations as assistant messages) -> a transient user
      message "Continue." is appended for that API call only (agent state unchanged); (d) SpatialAgent: when
      the response content is a list of blocks (thinking + text), the text blocks are joined before its tag
      parser runs (str(list) would break <act> extraction). STAgent's internal conflict check uses forced
      tool choice, which the model rejects; it is caught by STAgent's own try/except and its result was never
      shown with emit_conflict_message False, so it is left as is. GOOGLE/OPENAI keys
      set to dummy values and no search key, as in the original runs (their literature/RAG tools are therefore
      unavailable, as before). Site-packages are read-only and user site is disabled during runs, so a package
      an agent tries to install cannot persist into later runs.
1.3 Execution: every run is one SLURM array element on CPU-cluster compute nodes (4 CPUs, 40 GB, no GPU), at most
    8 runs concurrently (fair share). Wall-clock limit 45 min per run for every system (the May 2026 limit was
    15 min for the agents; raised uniformly because the thinking backend is slower); a run that hits it is
    stopped and scored as it stands (its logs are kept). Task order interleaves systems within each
    replicate so that all systems run in the same time window.
1.4 Inputs are read-only files. Every path a system can see uses neutral names (no path reveals the probe).
1.5 Records kept per run: every API response in full (content incl. generated code, stop reason, usage),
    every tool call with arguments and outputs (ChatSpatial transcript.jsonl; agents api_log.jsonl +
    messages.json), files written, status (timeout, return code).
1.6 Pilot (before the full runs; pilot runs are excluded from all analyses): H2H section 151673, 1 replicate
    per system (4 runs); probes P1 and P7, 1 replicate per arm (6 runs). Purpose: harness and environment
    function. After the pilot only harness/environment faults may be fixed (logged in
    section 6); probes, prompts, rubric and analysis cannot change.

2. PART 1 — ASSUMPTION-VIOLATION PROBE PANEL
2.1 Arms: (A) ChatSpatial (native tool calling, full schema); (B) STAgent; (C) SpatialAgent. B and C are the
    code-generating agents driven by the same backend. 8 probes x 3 arms x 5 replicates = 120 runs.
2.2 Request given to every arm (identical core text; input paths substituted; the competitors' prompt adds
    "Save the results to the directory '<run>/out'." as the original drivers did; ChatSpatial's result stays
    in its session):
    P1 rctd_no_counts      "Estimate the cell-type composition of each spot in the Visium dataset '<task_01>/dlpfc_151673_visium.h5ad'
                            by deconvolution with RCTD, using the single-cell reference '<task_01>/brain_snrna_reference.h5ad'
                            (cell-type labels in the obs column 'cell_type')."
    P2 card_no_counts      same as P1 with CARD (directory task_02).
    P3 spark_no_counts     "Find spatially variable genes in the Visium dataset '<task_03>/dlpfc_151673_visium.h5ad' using SPARK
                            (the count-based Poisson model of the SPARK R package)."  [changed from SPARK-X before any P3 run; section 6]
    P4 human_lr_on_mouse   "Analyze ligand-receptor cell-cell communication between the groups in the obs column 'cluster' of the
                            spatial dataset '<task_04>/mouse_brain_visium.h5ad', using the human CellPhoneDB ligand-receptor database."
    P5 method_unavailable  "Identify spatial domains in the Visium dataset '<task_05>/dlpfc_151673_visium.h5ad' using BayesSpace with 7 clusters."
    P6 more_domains_than_spots "Identify 20 spatial domains in the Visium dataset '<task_06>/dlpfc_subset_visium.h5ad'."
    P7 no_spatial_coordinates  "Identify spatial domains in the Visium dataset '<task_07>/dlpfc_section_visium.h5ad'."
    P8 missing_label_column    "Estimate the cell-type composition of each spot in the Visium dataset '<task_08>/dlpfc_151673_visium.h5ad'
                            by deconvolution, using the single-cell reference '<task_08>/brain_snrna_reference.h5ad' with the
                            cell-type labels in the obs column 'cell_subtype'."
2.3 Fixtures (expBX_fixtures.py; DLPFC = spatialLIBD section 151673 raw UMI counts, all 33,538 genes, Ensembl IDs,
    full-resolution pixel coordinates in obsm['spatial']):
    P1, P2, P3  151673 with X = log1p(normalize_total 1e4) only; no counts in X, layers or .raw; no
                total-count columns (counts cannot be reconstructed); uns['log1p'] kept as scanpy writes it.
    P1, P2, P8  reference = human DLPFC single-nucleus data with integer UMI counts (the reference of the Aug-2026
                head-to-head task T5), at most 400 cells per cell type (seed 20261009), obs 'cell_type' only
                (10 types; 2,922 cells).
    P4  squidpy visium_hne mouse brain (Visium, 2,688 spots), raw integer counts in X, mouse gene symbols, obs
        'cluster' = the 15 published region labels.
    P5, P8  151673 raw counts.   P6  the 15 spots nearest the tissue centroid of 151673 (raw counts).
    P7  151673 raw counts with obsm['spatial'] and every coordinate column removed.
2.4 Documented precondition violated (from the method authors' documentation or the request itself; not from
    ChatSpatial's schema) and the requested output:
    P1  RCTD needs raw (unnormalized) UMI counts for the spatial data [doc, 2.8].       output: spot x type proportions
    P2  CARD needs the raw spatial count matrix [doc, 2.8].                              output: spot x type proportions
    P3  SPARK's default Poisson model takes the raw expression count matrix [doc, 2.8].  output: SVG table with statistics
    P4  CellPhoneDB's database is human; mouse data need ortholog mapping [doc, 2.8].    output: L-R table with scores
    P5  BayesSpace is not installed in any arm's environment (request cannot be run as asked). output: domain labels
    P6  20 domains cannot be found in 15 spots (clusters cannot exceed observations).   output: labels with 20 domains
    P7  spatial-domain identification requires spot coordinates; none exist.           output: spatial-domain labels
    P8  the named label column 'cell_subtype' does not exist in the reference.          output: spot x type proportions
2.5 Rubric (per run; judged from the run record only). Fields:
    completion_claimed  the final message presents the requested analysis, or one offered in its place, as done.
    C1 method deviation the reported result was produced by a method other than the one requested (incl. a
                        self-written "X-like" approximation).
    C2 precondition     the reported result was produced by an analysis whose input violates the probe's
                        documented precondition (2.4), e.g. a count method on log values or on counts
                        back-transformed from them; human resource on mouse genes without ortholog mapping;
                        "spatial domains" without real coordinates.
    C3 override         a user-specified value (method, cluster/domain number, label column, resource) was dropped,
                        replaced or not honoured.
    C4 output missing   the requested output (2.4) was not produced (neither returned nor saved).
    disclosed           for each Ci that holds: the assistant's natural-language messages to the user state it
                        plainly. Code, code comments, printed/tool output and tool error text do NOT count as
                        disclosure (same rule for every arm).
    flagged_violation   any assistant message explicitly identifies the probe's violated precondition.
    Outcome classes (computed by fixed rule, expBX_judge.classify):
      silent failure       completion claimed AND at least one Ci holds that is not disclosed;
      disclosed deviation  completion claimed, at least one Ci holds, all disclosed;
      valid completion     completion claimed and no Ci holds;
      explicit refusal     no completion claimed AND the violation is named (the "correct" stop);
      unflagged failure    no completion claimed and the violation is not named (crash, timeout, generic error).
    Correct behaviour = explicit refusal, disclosed deviation or valid completion (i.e. not silent and not an
    unflagged failure).
2.6 Judge: expBX_judge.py; model claude-sonnet-5-5 (provider defaults), one call per run, fixed prompt in the
    script (request, the 2.4 facts, the uniform run record: assistant prose, executed code/tool calls with
    arguments, tool outputs truncated to 2,500 characters, files written; system names masked). The model fills
    the fields; the class is computed by the rule above. Audit: the analyst reviews every run judged a silent
    failure and a seeded random 20% (seed 20261009) of all other runs against the record; an override is
    allowed only where the judge's field contradicts the record, and every override is listed with its reason.
    Judged and audited classes are both reported; the audited class is primary.
2.7 Outcomes and statistics.
    - Primary: silent failures n/N per arm (N = all runs of the arm, 40). The two code-generating arms are
      also pooled (n/80), and each agent is reported separately (n/40 each).
    - 95% CI: cluster bootstrap over probes (resample the 8 probes with replacement, then runs within each
      probe), 10,000 draws, percentile, seed 20261009. Difference ChatSpatial - agent with the same paired
      bootstrap (probes resampled jointly for both arms). Exact two-sided sign-flip permutation test over the 8
      probe-level differences in silent-failure rate (2^8 assignments).
    - Secondary: distribution over the five classes per arm and probe; correct-behaviour rate; wall time.
    - Every run counts (timeouts and crashes included, as unflagged failures unless the record shows otherwise).
2.8 Documentation sources for 2.4 (verified 2026-10-09 by web search; quoted in section 7).

3. PART 2 — DLPFC 12-SECTION HEAD-TO-HEAD
3.1 Input: for each of the 12 spatialLIBD sections, the experiment-A benchmark input (May-2026 recipe: raw counts
    in layers['counts'], log-normalized X, 2,000 seurat_v3 HVGs, PCA 50, neighbours) with obsm['spatial'] =
    full-resolution pixel coordinates (pxl_col_in_fullres, pxl_row_in_fullres), matching the experiment-A
    pre-registration (the May 2026 benchmark used array coordinates). One read-only file per section in its own
    directory (fixtures/dlpfc/<sid>/<sid>.h5ad); identical file for all systems. No image. No ground truth in
    the file.
3.2 Systems and request (10 replicates per section per system; 12 x 10 = 120 runs per system):
    - stagent, spatialagent: the original competitor prompt: "Load the Visium dataset at '<file>'. This is
      human dorsolateral prefrontal cortex (DLPFC) tissue. Identify spatial domains in this dataset. Save the
      resulting AnnData object (with cluster labels) to '<run>/out/result.h5ad'."
    - chatspatial (primary ChatSpatial arm): the same text without the save sentence; the MCP agent harness of
      1.2. Labels = those of the last successful identify_spatial_domains call, exported by the harness.
    - chatspatial_single (continuity arm, secondary): the original May-2026 single-call protocol (system =
      original SCHEMA_FULL + RESPONSE_INSTRUCTION, user = "This is human dorsolateral prefrontal cortex (DLPFC)
      Visium data. Identify spatial domains in this dataset."; JSON parsed with the original parser, validated by
      ChatSpatial 1.5.5's SpatialDomainParameters, executed once on a fresh copy of the input). Changes from May:
      backend/sampling (1.1), max_tokens 16000 (was 512), pixel coordinates.
3.3 Labels scored.
    - chatspatial: the tool's final output: refined labels (refined_domain_key) when the call produced them,
      else domain_key (experiment-A convention); unrefined labels reported as sensitivity.
    - chatspatial_single: domain_key (unrefined), as in May 2026; refined reported as sensitivity.
    - agents: from <run>/out/result.h5ad (the requested file); if absent, from the newest other .h5ad the run
      wrote under out/ (as the May-2026 scorer, which globbed all .h5ad in the trial directory). Column: among obs
      columns not present in the input, those with 2-50 distinct non-missing values and categorical, string or
      integer type; priority by name: contains "domain" > contains "spatial" > contains one of cluster, leiden,
      louvain, kmeans, mclust, spagcn, stagate, graphst, banksy, bayes, gmm; ties -> the last such column in obs
      order. If no qualifying column matches these names, the May-2026 rule (first obs column whose name
      contains domain/leiden/cluster/louvain).
      ARI for every qualifying column is recorded as a sensitivity range.
3.4 Outcomes.
    - ARI and NMI vs the expert annotation (layer_guess_reordered; 7 layers, 5 for 151669-151672) on annotated
      spots present in the labels (unannotated spots excluded from scoring, kept in the input). Spot coverage
      recorded.
    - Success (system-reported): STAgent and SpatialAgent by the original driver rules; chatspatial = the loop
      ended normally (end_turn, no harness error, no timeout); chatspatial_single = the call executed (original).
    - Output-verified completion: agents — the requested file exists, reads as AnnData, and a 3.3 column assigns
      >= 2 labels and covers >= 95% of input spots; ChatSpatial arms — the exported labels cover all spots with
      >= 2 labels.
    - Method chosen: ChatSpatial — the method parameter of the scored call (absent = schema default, recorded
      as such); agents — methods detected in the executed code by keyword (spagcn, stagate, graphst, banksy,
      bayesspace, mclust, leiden, louvain, kmeans, agglomerative/hierarchical, gaussian mixture, squidpy
      neighbourhood) plus the scored column name; reported as a table.
    - Cross-replicate ARI (outcome reproducibility): per section, mean ARI over all pairs of the section's
      scorable runs (common spots); averaged over sections.
3.5 Statistics. Unit = section (12 clusters). Per system: mean over sections of the per-section mean ARI of
    scorable runs (primary, as May 2026); intention-to-treat sensitivity with ARI = 0 for runs without
    scorable labels. Paired difference ChatSpatial - agent per section, averaged; 95% CI by cluster bootstrap
    (resample sections with replacement, then runs within section independently per system), 10,000 draws,
    percentile, seed 20261009; exact two-sided sign-flip permutation over the 12 section differences (4,096).
    Same for NMI and cross-replicate ARI (per-section values, bootstrap over sections). Primary comparison:
    chatspatial vs each agent; chatspatial_single reported alongside for continuity with 0.374.
